02

Run it in your cloud

One stateless container on port 8000, configured entirely through environment variables. It does not terminate TLS — whatever you put in front of it already does, which is what lets it run anywhere.

What you need

A container runtime. That is the whole list. No database to provision, no OAuth app to register, no certificate, no config file, no accounts created in advance. Then, depending on what you are doing:

Anything you would missSECRET_ENCRYPTION_KEY, or values are stored unencrypted
Clients on other machinesBACKEND_URL, and TLS in front of it
Not publicly signup-ableALLOW_REGISTRATION=false
More than one replicaDB_URL at Postgres, and a fixed BOOTSTRAP_TOKEN
A specific listen portPORT — honoured on Cloud Run and similar
OPTION 01

Docker

That is the whole setup. It brings its own database and issues its own tokens. Published for amd64 and arm64.

docker run -d -p 8000:8000 \ -v secretmgr-data:/data \ ghcr.io/clement880101/secret-manager:latest

For anything real, add SECRET_ENCRYPTION_KEY to encrypt values at rest and BACKEND_URL for the address clients reach.

OPTION 02

Compose

The API and a Postgres with a persistent volume, together.

Anywhere else

Fly.io, Render, Railway, Cloud Run, Azure Container Apps and Kubernetes all build from the same Dockerfile, and terminate TLS for you.

Pick a database

SQLite is bundled and is the default, written to the /data volume. Nothing external needed for a single instance.

Point DB_URL at Postgres for more than one replica — the driver ships in the image too. A database inside the app container would give each replica its own copy.

Scale past one replica

Login state lives in the database, not in process memory, so a login can start on one instance and finish on another.

An OAuth state is claimed with a conditional UPDATE, so a replayed callback loses even when it arrives concurrently.

Encrypt at rest

Set SECRET_ENCRYPTION_KEY and values are encrypted before they reach the database. Keep the key — losing it makes existing values unreadable.

docker run --rm \ ghcr.io/clement880101/secret-manager:latest \ python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

Then make it runnable

Downloads arrive without the executable bit. Rename it, mark it executable, put it on your PATH:

chmod +x secretmgr-* && sudo mv secretmgr-* /usr/local/bin/secretmgr

Check it: secretmgr ping → API healthy.

On macOS, the first run

These builds are not code-signed, so Gatekeeper refuses them until you say otherwise. Clear the quarantine flag:

xattr -d com.apple.quarantine /usr/local/bin/secretmgr

Or open it once from Finder with right-click → Open.

Verify what you downloaded

Every release ships a SHA256SUMS file built alongside the binaries.

shasum -a 256 -c SHA256SUMS --ignore-missing

04

How it works

STEP 01

Sign yourself up

secretmgr register creates an account on that deployment. No invitation, no GitHub. Close sign-ups with ALLOW_REGISTRATION=false, or configure a GitHub OAuth app to use browser logins instead.

STEP 02

Store a key and value

Secrets are scoped to you. Keys are unique per account, so a second create on the same key is refused rather than silently overwriting.

STEP 03

Share with a teammate

Grant read access by whatever name you issued their token under. They see it in their own list; only you can delete or re-share it.

06

Before you trust it with anything

Before you put real secrets in it

  • Set SECRET_ENCRYPTION_KEY and back it up. Without it values are stored unencrypted; lose it and they are unreadable, permanently.
  • Put TLS in front. The service speaks plain HTTP by design so it fits any platform. The CLI warns when it is talking cleartext to a remote host.
  • list returns values in plaintext, so a stolen token exposes everything that account can see at once.
  • Authentication is rate limited; the rest of the API is not. Failed logins are blocked per username and per address, but a valid token can be replayed as fast as the service answers.
  • No audit log and no account recovery. The service does not record who read what, and a forgotten password needs an administrator to issue a token.
  • Released binaries are unsigned. Verify the published SHA-256 checksums.
